# Docker Manage 当前环境变量快照设计

日期：2026-07-29

## 目标

让 `package-docker-app` 把项目根目录下的 `.docker-manage/.env` 作为项目级“当前最新有效配置”：

- `inspect` 发现环境变量后，读取并展示对应的当前配置值。
- 当前配置值优先于源码、Compose、Dockerfile 中声明的默认值。
- 用户回复“无修改”时沿用当前配置值。
- 只有一次打包完整成功后，CLI 才原子更新 `.docker-manage/.env`。
- `.docker-manage/work/<run_id>/state.json` 继续只保存单次任务状态，不承担跨任务配置复用职责。

这样可以让多个任务共享一个明确的配置快照，同时避免从若干历史 `run_id` 中猜测哪一个代表当前配置。

## 文件职责

`.docker-manage` 保持以下职责划分：

```text
.docker-manage/
├── .env                  # 最近一次成功打包使用的项目级环境变量
├── .gitignore
├── generated/            # 模型生成的 Docker 配置
├── work/
│   └── <run_id>/         # 单次任务的临时状态和工作文件
└── dist/                 # 已验证的离线部署归档
```

`.docker-manage/.env` 是 CLI 管理的快照文件，不是新的 Compose `env_file`，也不参与源码树的普通文件扫描。`state.json` 在 `inspect -> plan -> package` 各阶段之间继续保存检查结果、计划、计划哈希和制品状态；正常任务完成后仍按现有规则清理。

## 当前配置读取

### 读取时机

CLI 在完成源码、Compose 和 Dockerfile 的环境变量发现后读取 `.docker-manage/.env`。文件不存在时返回空快照，行为与当前版本完全一致。

只为已经由确定性扫描或模型补充明确发现的 `(service, name)` 环境变量匹配当前值。快照中的未知键不生成新问题，也不绕过“只报告明确环境变量读取”的现有约束。

### 键名匹配

快照使用部署制品现有的 `artifact_name` 规则。对于服务 `web` 的容器变量 `PORT`，按以下顺序查找：

1. 服务专属键 `WEB_PORT`。
2. 通用键 `PORT`。
3. 如果两者都不存在，则使用源码、Compose 或 Dockerfile 的唯一声明默认值。

服务专属键优先，使多个服务可以为同名容器变量保存不同值；通用键兼容多个服务共享同一值的情况。服务名前缀的规范化逻辑必须与规划阶段生成 `artifact_name` 的逻辑共用同一个函数，不能分别实现。

### 检查快照

`inspect` 把本次读取到的当前值及来源 `.docker-manage/.env` 一起保存到 `Inspection`。这是一项向后兼容的可选数据：旧状态没有当前值时仍可读取。

保存检查时快照可以保证：即使用户在 `inspect` 与 `plan` 之间修改根目录 `.docker-manage/.env`，本次任务的问题默认值和计划仍基于检查时看到的同一份配置。重新运行新的 `inspect` 才会读取新值。

## 问题展示和默认值

环境变量问题明确区分“当前配置值”和“声明默认值”：

```text
1. 设置 web.PORT。当前配置值：8322，来源：.docker-manage/.env；
   声明默认值：8000，来源：app.py:2，默认值：8322
```

具体规则：

- 有当前配置值时，`Question.default` 使用当前配置值。
- 没有当前配置值时，继续使用唯一声明默认值。
- 没有当前配置值且声明默认值冲突时，继续标记为必填。
- 当前配置值即使不同于一个或多个声明默认值，也不构成冲突；提示中仍完整展示声明值及来源。
- 当前配置为空字符串时视为有效值，不回退到声明默认值。
- 技能和 CLI 继续完整显示密码、Token 和 Key，不脱敏，保持现有契约。

因此用户回复“无修改”时，稀疏环境变量解析会自动采用当前配置值；用户仍可用 `序号: 值` 覆盖。

## 成功后更新快照

CLI 使用最终 `PackagePlan.environment` 生成新快照，键为 `artifact_name`，值为用户确认并实际打包使用的值。

更新时间点必须满足以下条件：

1. Docker 构建、拉取和导出已经完成。
2. 部署 Compose、制品 `.env`、manifest 和校验和已经验证。
3. 最终归档已经成功创建并通过归档校验。

满足这些条件后，CLI 才写入 `.docker-manage/.env`，随后把任务状态转换为 `packaged`。如果前面的任何步骤失败，现有快照保持不变。

写入采用同目录临时文件、`fsync` 和 `os.replace`：

- 新文件权限固定为 `0600`。
- `.docker-manage` 目录继续保持 `0700`。
- 替换失败时保留旧快照，并把本次任务视为失败。
- 文件由 CLI 完整重写为本次计划中的有效环境变量；变量按键名排序，值使用 dotenv 安全引用。

完整重写保证快照精确代表最近一次成功打包使用的配置，不保留已经从项目或计划中删除的陈旧变量。

`--dry-run`、只执行 `inspect`、只执行 `plan`、等待模型补充和失败任务都不得更新快照。

## 组件设计

### 当前配置模块

新增一个独立模块，负责：

- 解析 `.docker-manage/.env`。
- 按服务专属键、通用键的优先级匹配已发现变量。
- 提供共享的服务名前缀规范化函数。
- 把最终计划环境变量原子写回快照。

该模块不负责扫描业务源码、不生成问题、不构建计划，避免把持久配置策略混入 `envscan.py`。

### 数据模型

`EnvCandidate` 增加一个可选的当前配置值字段，内容包括完整值和来源。字段缺失时采用现有行为，从而允许读取当前分支产生的旧 `state.json`。

不把当前配置伪装成普通声明默认值，否则当前值与源码默认值不同时会错误地产生“默认值冲突”。

### CLI

`inspect` 在 `scan_environment()` 和模型补充合并完成后，把当前配置附加到环境变量候选并保存进任务状态。

`package` 在归档验证成功后调用快照原子写入接口。模型不得直接编辑 `.docker-manage/.env`；所有读取和写入都由随附 CLI 完成。

### 技能说明

`SKILL.md` 增加以下契约：

- 展示每个环境变量的完整当前配置值和声明默认值。
- 当前配置值存在时，未覆盖项自动采用该值。
- 明确说明 `.docker-manage/.env` 只在打包完整成功后更新。
- 计划确认仍需完整列出最终环境变量值，不能因为值来自当前快照而省略。

## 错误处理

- `.docker-manage/.env` 不存在：视为空快照。
- 文件无法读取或 dotenv 结构无法提供已匹配键的具体值：返回中文 `UsageError`，不静默改用声明默认值。
- `KEY=` 表示有效的显式空字符串。
- 只有键名、没有等号和值的已匹配项视为无效配置。
- 未知键忽略；它们不会进入检查结果或最终计划。
- 快照原子替换失败：本次打包失败，旧快照保持不变。
- 当前配置值包含密码、Token 或 Key：按现有安全模型完整展示，并只写入权限为 `0600` 的状态、快照和制品文件。

## 兼容性

- `.docker-manage/.env` 不存在时，现有问题、默认值、计划和制品行为保持不变。
- 现有 Compose `.env` 和 `env_file` 发现逻辑保持不变。
- 答案 JSON 格式、问题 ID、命令参数、计划哈希和归档结构保持不变。
- 历史 `state.json` 不会被扫描为当前配置，也不会参与任务选择。
- 正常完成后的工作目录清理规则保持不变。

## 测试

### 单元测试

- 快照不存在时返回空结果。
- 通用键 `PORT` 应用于发现了 `PORT` 的服务。
- 服务专属键 `WEB_PORT` 优先于通用键 `PORT`。
- 多服务同名变量可分别读取 `WEB_PORT` 和 `WORKER_PORT`。
- `KEY=` 被读取为空字符串。
- 未知键不会生成新的环境变量候选。
- 当前配置值优先成为问题默认值，同时声明默认值及来源仍完整展示。
- 当前配置与声明默认值不同不会被标记为冲突。
- 原子写入生成 `0600` 文件并按键名排序。
- 写入失败时旧快照内容保持不变。

### 集成测试

- `inspect --json` 返回当前配置值、来源及以当前值为默认值的问题。
- `inspect -> plan` 使用“无修改”等价的默认展开后，计划采用当前配置。
- `.docker-manage/.env` 存在未知键时，检查结果不新增问题。
- 旧状态中没有当前配置字段时仍能执行 `plan`。

### 端到端测试

执行两次打包：

1. 首次通过答案文件选择一个不同于源码默认值的环境变量。
2. 断言首次完整成功后 `.docker-manage/.env` 保存该值。
3. 发起第二次 `inspect`，断言问题展示该值为当前配置和默认选择。
4. 第二次不覆盖环境变量，断言计划和制品继续使用该值。

另增加失败路径测试，证明归档完成前的错误不会覆盖已有快照。

## 非目标

- 不从多个 `work/<run_id>/state.json` 推断“最新任务”。
- 不把 `.docker-manage/.env` 当作业务 Compose 的 `env_file`。
- 不从快照中的未知键推断新的运行时配置。
- 不保留快照中的注释、空行顺序或已经失效的未知变量。
- 不改变 `state.json` 在任务阶段之间的流程协调职责。

## 完成标准

- `.docker-manage/.env` 始终表示最近一次完整成功打包所使用的环境变量。
- 新任务优先展示并采用该快照中的匹配值。
- 多服务同名变量可无歧义地往返保存和读取。
- 失败、检查、规划及 dry-run 不会改变当前快照。
- 没有快照的项目保持原有行为。
- 全量自动化测试和技能校验通过。

# 环境变量稀疏覆盖与中文输出设计

日期：2026-07-28

## 目标

改进 `package-docker-app` 的环境变量配置体验，并确保所有面向用户的自有文本使用中文：

- 环境变量一次性按稳定序号列出，用户只提交需要覆盖的值。
- 未提交且具有唯一默认值的环境变量自动沿用默认值。
- 未提交且没有默认值或默认值冲突的环境变量只追问缺失项。
- 大模型对话、技能说明、CLI 帮助、交互提示和自有错误信息统一使用中文。
- 保持现有 JSON 字段、问题 ID、枚举值、命令名和参数名兼容。

## 范围

本次修改覆盖：

- `skills/package-docker-app/SKILL.md` 中给大模型的完整工作流和输出语言约束。
- CLI 交互模式中的环境变量收集方式。
- CLI 生成的问题文案、帮助信息、提示标签和项目自有错误信息。
- 模型补充文件中的用户可见歧义问题生成规则。
- 单元、集成、端到端和技能契约测试。

以下内容保持原样：

- `inspect`、`plan`、`package`、`run` 等命令和参数名。
- JSON 字段名、问题 ID、阶段值和内部枚举值。
- Docker、Git、操作系统和其他第三方工具返回的原始输出。项目提供中文上下文，但不翻译原始输出，以免改变诊断证据。
- 已有答案文件格式 `{"values":{"question.id":"answer"}}`。

## 环境变量交互协议

### 展示

环境变量问题继续由 CLI 按 `(service, name)` 排序生成。大模型和交互式 CLI 使用相同顺序，为本轮环境变量列表分配从 `1` 开始的序号。

示例：

```text
1. web.PORT，默认值：8000
2. web.API_KEY，必填，无默认值
3. worker.LOG_LEVEL，默认值：info
```

如果同一变量发现多个不同默认值，则完整显示默认值及来源，并将该项标记为“必填，默认值冲突”。不得擅自选择其中一个默认值。

### 输入

用户只提交覆盖项，每项使用 `序号: 值`：

```text
1: 8080
2: secret
```

输入规则：

- 冒号两侧允许空白。
- 值保留用户输入内容；使用 `<EMPTY>` 表示显式空字符串。
- 未提交且有唯一默认值的项自动填入默认值。
- 未提交且无默认值或默认值冲突的项不自动填充，只追问这些序号。
- 重复序号、越界序号、缺少冒号和非数字序号均作为输入错误处理，并用中文指出问题。
- 大模型对话中，全部采用默认值时可回复 `无修改`。
- 终端交互中以空行结束输入；第一行为空表示没有覆盖项，也接受 `无修改`。

解析完成后，仍将所有环境变量映射回原有 `env.<service>.<name>` 问题 ID。答案文件和后续规划逻辑因此不需要协议变更。

### 非环境变量问题

构建参数、端口、第三方镜像、外部文件和模型歧义问题继续按现有顺序处理。它们不使用环境变量序号协议，但所有提示、选项说明和错误信息改为中文。机器值如 `yes`、`no`、`keep_server_path` 和 `abort` 保持不变；展示时提供中文含义。

## 组件设计

### `questions.py`

保留 `Question` 数据模型和问题 ID。新增独立的环境变量批量展示与稀疏解析逻辑，使 CLI 和技能工作流共享以下规则：

- 识别并稳定排序环境变量问题。
- 生成带序号的中文展示行。
- 解析多行 `序号: 值` 输入。
- 合并覆盖值与默认值。
- 返回缺失的必填项和具体中文校验错误。

现有单项 `parse_answer` 继续处理非环境变量以及最终值规范化。

### `cli.py`

交互模式先批量收集所有环境变量，再逐项询问其他问题。非交互模式仍从答案 JSON 按问题 ID 读取；调用方必须提供完整答案，现有自动化接口不发生隐式行为变化。

CLI 增加中文说明、参数帮助和错误标签。命令语法本身不翻译。

### `SKILL.md`

技能正文和描述改为中文，并明确要求：

- 所有面向用户的解释、提问、计划和结果使用中文。
- 环境变量按 CLI 返回顺序一次性编号展示。
- 只接收稀疏覆盖项，代理负责将默认值和覆盖值展开为完整答案 JSON。
- 缺失必填项时只追问缺失序号。
- 模型补充中的 `ambiguities.prompt` 和面向用户的选项说明使用中文。
- 技术标识、命令、路径和机器协议保持原文。

### 其他模块

项目自有的异常消息和提示统一翻译为中文。第三方 stderr/stdout 继续放入 `details` 原样输出，并由中文错误摘要与修复提示包裹。

## 错误处理

- 稀疏输入格式错误时不丢弃已经展示的列表，提示错误行并要求重新提交。
- 必填环境变量缺失时列出缺失序号、服务名和变量名，不重复要求填写已有默认值的项目。
- 单个覆盖值不满足原有问题约束时，沿用原校验逻辑并返回中文错误。
- 非交互答案文件缺项时继续以退出码 `10` 失败，错误信息改为中文。
- CLI 参数错误、状态错误、Docker 操作错误和制品校验错误保留原退出码。

## 兼容性

此次修改不改变持久化模型、补充文件 schema、答案文件 schema、计划哈希算法或归档结构。已有脚本若使用完整答案 JSON，行为保持不变。只有交互展示和人类输入协议发生变化。

## 测试

测试至少覆盖：

- 环境变量序号稳定且从 `1` 开始。
- 只覆盖部分值时，其余唯一默认值自动填充。
- `无修改` 和终端首个空行采用全部可用默认值。
- 无默认值及默认值冲突项必须显式填写。
- `<EMPTY>` 生成空字符串。
- 重复、越界、非数字和缺少冒号的输入返回中文错误。
- CLI 交互先批量处理环境变量，再处理其他问题。
- CLI 帮助、问题文案、错误标签和项目自有错误信息为中文。
- `SKILL.md` 包含中文输出和稀疏覆盖契约。
- 现有非交互 JSON、计划、打包和端到端流程继续通过。
- 技能目录通过官方快速校验。

## 完成标准

- 大模型执行技能时不再要求用户为未修改的环境变量逐项填写 `默认`。
- 用户可以仅用 `序号: 值` 提交修改项。
- 除机器协议、技术标识和第三方原始输出外，用户看到的项目文本均为中文。
- 全量自动化测试与技能校验通过。
